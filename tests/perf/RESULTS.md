# Performance test — 50,000 rows × 20 columns

Generated by `tests/perf/perf50k.mjs` on 2026-11-13.
Host: Intel(R) Xeon(R) Processor @ 2.10GHz, 4 cores, 16 GB RAM, headless Chromium, Pixel 7 viewport (412×915 @2.6x), touch input.
File: 1 sheet, 50,000 data rows, 20 columns (numbers, text, dates) and one SUM formula per row (50,000 formulas).
Tier per column: **high** / **mid** (High = 10k-row load chunks, native pixel ratio; Mid = 4k-row chunks, grid canvas capped at 2x). Override with `TIER=low|mid|high`.

Notes
- Headless Chromium on a server has **no GPU**: the canvas is rasterised and composited in software on the
  main thread, and 60 Hz is the ceiling. Under CPU throttling that software raster (`drawImage` / native
  "program" time in a profile) is >75 % of each frame while the app's own JavaScript is <10 %, so the throttled
  FPS is a pessimistic bound. Android WebView composites the grid canvas on the GPU; on a 120 Hz panel in the
  High tier the app requests the highest refresh rate.
- CPU throttling slows JavaScript but not memory bandwidth/IO, so it is only an approximation of a phone.
- Re-run on a real device with `chrome://inspect` (debug APK) → Performance panel for exact numbers.
